# Osverse 0.6 — Qwen Code 安全接入与回归加固

Osverse 0.6 把 Qwen Code 纳入统一的检测、安装、启动、API 配置和安全移除流程。Linux x64 与 Windows x64 可以直接使用；Linux arm64 与 macOS x64/arm64 的官方独立制品元数据也已固定，安装器会随对应的 Osverse 平台版本启用。

## 重点变化

- “核心 CLI”新增 Qwen Code：系统中任何真实可执行路径上的现有 `qwen` 都能被发现，无需迁移到 Osverse 目录。
- Osverse 可以安装官方 Qwen Code `v0.21.13` standalone 包；包内自带 Node.js，不要求预装或修改系统 Node/npm。
- Linux 与 Windows 使用各自的用户级受管命令入口。安装、更新、启动和移除均沿用计划确认、真实路径复核和恢复机制。
- API 兼容矩阵新增 Qwen Code。OpenAI Chat Completions 探测通过后，可把精确模型 ID、Base URL 和 Key 应用到 `~/.qwen/settings.json`。
- Qwen 配置使用内置 `openai` 协议启动，并同时固定 `model.name` 与 `model.baseUrl`；像 `deepseek/deepseek-v4-flash` 这样的模型 ID 会原样发给 API，不会添加 `osverse/` 前缀。

## 安装安全

- 五个平台制品的版本、官方下载 URL、精确字节数与 SHA-256 固定在后端；0.7.1 起只允许 GitHub 下载所需的一次官方 HTTPS 资产跳转，其他重定向全部拒绝。
- tar/zip 展开只接受固定的 `qwen-code/` 根目录，并拒绝路径穿越、符号链接、硬链接、设备文件、Windows 保留名、过多条目与解压体积异常。
- 提交前使用包内 Node.js 运行官方入口并精确验证版本。同版本复用会重新哈希 Node、入口脚本、上游启动器和 Osverse wrapper，损坏或被替换的运行时不会被信任。
- Linux 使用不可变版本目录与原子符号链接；Windows 使用带所有权标记的每用户 shim。外部同名命令不会被静默覆盖。
- 官方 Linux tarball 已完成真实安装、启动和模拟 API 请求回归；官方 Windows zip 已完成哈希、展开和入口结构验证。Windows x64 与 macOS x64/arm64 还会在 CI 中编译。

## API 配置

Osverse 会先备份并原子更新 Qwen 用户设置，保留无关字段和其他 provider。Key 只写入当前用户可读的 `0600` 设置文件及受保护备份，不会出现在 Osverse 的档案列表、历史或日志中。移除 Qwen Code 时，配置、凭据和会话默认保留。

详情见仓库中的 [Qwen Code 接入指南](https://github.com/Oswald-Hao/Osverse/blob/main/docs/guides/qwen-code.md)。

## English summary

Osverse 0.6 integrates Qwen Code into discovery, verified per-user installation, launch, API-profile application, and recoverable removal. Linux x64 and Windows x64 are enabled in the app. The official Qwen Code `v0.21.13` standalone runtime includes its own Node.js, so no global Node/npm installation is required.

Every artifact is pinned by official URL, exact length, and SHA-256. Redirects, traversal, links, special files, hazardous Windows names, excessive entries, and excessive expansion are rejected. Before activation, Osverse runs the bundled Node.js against the official CLI entry and requires the exact version. Critical files are rehashed before any same-version runtime is reused.

Confirmed OpenAI Chat Completions profiles can be applied to Qwen without changing the model ID. Osverse selects Qwen's built-in `openai` protocol and pins both the exact model and Base URL, preventing a same-name model from routing to a different endpoint. A real standalone integration test verifies that `deepseek/deepseek-v4-flash` reaches the mock API unchanged.
