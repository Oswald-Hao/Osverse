# Osverse 0.7 — GitHub Copilot CLI 安全接入

> **0.7.3 网络与界面修复：** 已验证的本机代理协议和端口现在按当前用户持久保存，切换页面或重启 Osverse 后无需重新绑定；选择直连会清除保存值，且只保存协议与端口，不保存凭据或修改系统代理。更新发现改用官方 GitHub Release Atom feed，避免共享出口 IP 的匿名 REST API 限流导致 `UPDATE_FAILED`，下载仍严格校验固定仓库、清单、文件名、长度与 SHA-256。代理探测延迟按 `≤500ms` 绿色、`501–1000ms` 黄色、`>1000ms` 红色展示。所有受支持 CLI、桌面应用和管理工具卡片加入本地 SVG 图标，不依赖远程图片。

> **0.7.2 安装事务修复：** Qwen Code 与 DeepSeek Harness 在最终命令激活失败时，会删除本次新写入的运行时；已经存在且重新校验通过的同版本运行时会保留。Windows 上 Claude Code、Codex CLI 与 OpenCode CLI 的版本目录、命令 shim 和用户 PATH 现在也属于同一安装事务，并会在失败时恢复；复用已有 Windows 版本前会逐项哈希比较完整目录与刚验证的 staging 内容。若任何回滚动作本身失败，界面会明确要求刷新扫描确认残留状态，不再错误显示“未安装”。同时，OpenCode Desktop、CC Switch 与 Cockpit Tools 的 GitHub 制品统一使用精确的一次官方 HTTPS 资产跳转策略。

> **0.7.1 下载修复：** 修正 Qwen Code 与 Copilot CLI 的 GitHub Release 下载策略。GitHub 的官方下载端点会正常返回一次 `302` 到专用资产域名；0.7.0 错误地拒绝了这次跳转，导致界面显示下载失败。0.7.1 仅允许从精确 `github.com` 原始地址到 `release-assets.githubusercontent.com` 的一次 HTTPS 跳转，仍拒绝任意域名、HTTP、显式端口、用户信息、片段、篡改来源和二次跳转，并继续校验精确长度与 SHA-256。官方 Qwen Linux x64 83.5 MB 制品已通过真实在线下载回归。

Osverse 0.7 将 GitHub Copilot CLI 纳入现有工具发现、事务式安装、启动与安全移除流程。Linux x64 与 Windows x64 应用启用安装；Linux arm64 与 macOS x64/arm64 的官方制品元数据已经固定，为后续平台发版做好准备。

## 重点变化

- 发现任意真实用户命令路径中的 `copilot`，无需搬入 Osverse 目录。
- 安装 GitHub 官方 Copilot CLI `v1.0.80` standalone 包，不修改全局 Node/npm。
- 五个平台制品固定官方 URL、精确字节数和 SHA-256；只允许 GitHub 所需的一次官方 HTTPS 资产跳转。
- tar/zip 只允许一个固定名称的普通可执行文件；路径穿越、链接、额外条目和异常展开会失败。
- 提交前运行官方二进制并精确验证版本；同版本复用会重新哈希关键文件。
- 受管命令固定启用 `--no-auto-update`，避免上游更新绕过 Osverse 的统一验证和回归门禁。
- 安装末段命令激活失败时，新写入的版本目录会回滚；已有的已验证版本不会被删除。

## 登录与 API

首次启动可按提示登录，或运行 `copilot login`。用户需要有效的 GitHub Copilot 订阅。Copilot CLI 不使用 Osverse 的通用第三方 API 档案，因此 Osverse 不会向其写入 API Key、Base URL 或模型配置；登录凭据也不会由 Osverse 读取。

## 验证

官方 Linux x64 tarball 已完成真实解压、版本执行、Manager 下载替身、安装、wrapper 启动与任务状态回归。官方 Windows x64 zip 已完成精确大小、SHA-256、单文件结构、安全展开与 PE 文件头验证。全仓测试、race、vet、前端 57 项测试、Windows x64 全仓交叉编译，以及 macOS x64/arm64 安装器编译均已通过。

## English summary

Osverse 0.7 adds GitHub Copilot CLI discovery, verified per-user installation, launch, and recoverable removal. It pins the official `v1.0.80` standalone artifacts by URL, exact byte count, and SHA-256 for five targets. Extraction accepts exactly one fixed-name regular executable, exact version verification is required before activation, and the managed wrapper disables upstream self-update so upgrades remain inside Osverse's tested release boundary.

Copilot authentication and subscription remain owned by GitHub. Generic Osverse API profiles are deliberately not applied to Copilot CLI. Failed final activation rolls back a newly committed runtime instead of leaving the UI and filesystem in conflicting states.

Version 0.7.2 extends that transaction guarantee to Qwen Code, DeepSeek Harness, and the generic Windows CLI installer. A failed final activation removes only a newly committed runtime, preserves an already verified version, and reports any rollback failure without claiming that nothing was installed. Existing Windows payloads must match the complete freshly verified staging tree before reuse. GitHub-hosted desktop artifacts now share the same exact one-hop HTTPS release-asset policy introduced in 0.7.1.

Version 0.7.3 persists the verified loopback proxy protocol and port for the current user, switches update discovery to GitHub's official Release Atom feed to avoid anonymous REST rate-limit failures on shared proxy exits, and keeps the existing strict manifest, platform, filename, size, and SHA-256 verification. Proxy latency is now green at 500 ms or below, yellow from 501 through 1000 ms, and red above 1000 ms. Every supported CLI, desktop app, and management tool card now has a bundled local SVG icon.
