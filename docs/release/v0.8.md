# Osverse 0.8 — DeepSeek Harness API 档案接入

Osverse 0.8 把已保存并通过协议探测的第三方 API 档案直接接入 DeepSeek Harness。用户只需在 Osverse 填写 API Key、Base URL 和服务商提供的精确模型 ID，探测成功后勾选 **DeepSeek Harness**、预览并确认写入；新建的 Harness 会话随后直接使用该档案。

## 重点变化

- 支持 OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages；多个协议可用时按经过测试的顺序自动选择。
- 在 `$DSH_HOME/settings.yaml` 中维护独立的 `llm-pi-ai.providers.osverse` Provider，并更新新会话默认模型。
- 模型 ID 保持服务商原始值，例如 `deepseek/deepseek-v4-flash`；`osverse` 只是 Harness 的 Provider 路由，不会被写进模型 ID。
- API Key 只写入 `$DSH_HOME/.credentials.yaml` 的 `OSVERSE_API_KEY`；普通设置只保存凭据引用。
- 保留无关 Provider、设置、注释与凭据；已经发送过请求的 Harness 会话仍保留自身记录的模型。

## 写入与回滚安全

- 两份原文件在写入前打包到当前用户私有备份目录，目标文件与备份使用当前用户私有权限。
- 使用锁定版 Harness `0.1.0-rc.6` 的官方同名 `.lock` 约定协调运行中的 Harness，并以原子替换提交文件。
- 凭据提交、设置提交或写后验证任一步失败时自动恢复原文件；即使底层写入在替换后才报告错误，也按可能部分落盘处理。
- 拒绝覆盖非 Osverse 所有的同名 Provider 或孤立凭据，拒绝相对路径、主目录外路径、符号链接、重复 YAML 键、多文档 YAML 与不安全的 POSIX 凭据权限。
- `DSH_HOME=~` 可正常使用，且不会修改用户主目录原有权限。

## English summary

Osverse 0.8 applies a saved and protocol-verified third-party API profile directly to DeepSeek Harness. It maps confirmed OpenAI Chat Completions, OpenAI Responses, or Anthropic Messages support into an owned `llm-pi-ai.providers.osverse` route, selects the vendor's exact model ID for new sessions, and stores the key only in Harness's credential document.

Settings and credentials are backed up and committed as one recoverable operation using the pinned Harness release's lock convention and atomic replacement. Unrelated YAML, comments, providers, and credentials are preserved. Unsafe paths, symlinks, duplicate or multi-document YAML, insecure POSIX credential files, and unowned `osverse` names are rejected rather than overwritten.

The release was validated with a real pinned Harness headless request, full Go tests/race/vet/coverage, 61 frontend tests and audits, native Ubuntu 20.04/22.04 packages, and native Windows tests plus NSIS install/launch/remove smoke.
