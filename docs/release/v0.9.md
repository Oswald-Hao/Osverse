# Osverse 0.9 — Kimi Code 跨平台接入

Osverse 0.9 将 Kimi Code 纳入统一的检测、校验安装、启动、移除和第三方 API 档案流程。已有外部 `kimi` 无需搬家；需要安装时，Osverse 使用 Moonshot AI 官方独立二进制，不依赖 Node/npm。

## Beta 2 热修复

- 修复 Windows 和 Linux 启动 DeepSeek Harness 时丢失 `DSH_HOME` 的问题。Osverse 现在会让 Harness 打开与 API 配置页相同的 profile home，不再因配置与启动落到两个不同目录而出现 profile 找不到、冲突或无法加载。
- Windows CI 新增真实首次启动门禁：从嵌入的完整性锁构建官方 Harness 运行时，初始化一个全新的 `web` profile，并等待浏览器页面实际可访问。仅执行 `dsh --version` 不再是 Windows profile 兼容性的唯一依据。

## Beta 3 热修复

- 修复 Windows 上点击启动 DeepSeek Harness 仍不可用的问题。Osverse 现在在终端启动 `.cmd`/`.bat` 命令入口时使用 Windows 批处理语义所需的 `call`，避免托管 `dsh.cmd` 包装器链路行为异常。
- 修复 Windows 上无法删除 Osverse 托管 DeepSeek Harness 的问题。删除计划现在会识别 Harness 的托管 `.cmd` wrapper，同时仍只允许目标位于当前用户的 Osverse 管理目录中，不放宽其它 CLI 的 `.exe` 安全边界。
- Windows CI 进一步覆盖真实 Osverse 托管入口链：外层 `%USERPROFILE%\.local\bin\dsh.cmd` → 版本目录 `bin\dsh.cmd` → 内置 Node.js → Harness `web` profile，并继续验证安装、启动和删除烟测。

## Beta 4 热修复

- 修复 Windows 上其它 Osverse 托管 `.cmd` wrapper CLI 的安全删除：Qwen Code、Kimi Code 和 GitHub Copilot CLI 现在与 DeepSeek Harness 一样，可以在外层 shim 指向对应组件管理目录中的命令 wrapper 时生成删除计划。
- 删除验证仍要求 wrapper 文件名与组件命令精确匹配，并且目标必须位于当前用户的 Osverse 管理目录内；不匹配的 `.cmd` 目标继续拒绝，避免把任意脚本当作 Osverse 托管组件移动。

## Beta 5 热修复

- Windows 现在识别 OpenCode 官方 Beta 通道的 `OpenCode Beta` 安装记录、`OpenCode Beta.exe`、默认当前用户安装目录和对应卸载器；标准版、旧版 `@opencode-aidesktop` 与注册表记录的自定义安装目录继续兼容。
- 修复桌面端与 CLI 同名导致的误报：Windows 文件名不区分大小写，PATH 中的 `claude.exe`、`codex.exe` 或 `opencode.exe` 不再单独作为 Claude、Codex 或 OpenCode 桌面端已安装的证据。固定桌面路径、卸载注册表和不冲突的桌面入口仍会正常检测。
- Windows 原生回归覆盖 OpenCode Beta 默认路径、注册表自定义路径、CLI/桌面同名隔离与安全卸载，并继续通过 DeepSeek Harness 新 profile、NSIS 打包和安装/启动/删除烟测。

## Beta 6 热修复

- Windows Store/MSIX 检测现在要求精确的应用包身份边界，不会把 `OpenAI.CodexPreview` 等相邻包误认为 Codex；同一应用存在多个注册版本时，按确定性规则选择最高的有效数字版本。
- Windows 卸载注册表中的 `REG_EXPAND_SZ` 安装目录和图标路径会通过系统 API 安全展开，因此 `%LOCALAPPDATA%` 等自定义安装位置不再被误报为“有安装记录但找不到可执行文件”。普通 `REG_SZ` 保持原样，未解析变量、相对路径和控制字符继续拒绝。
- DeepSeek Harness 的 Windows 运行时提交改用不覆盖目标的 Win32 原子移动；遇到杀毒扫描、索引或刚结束进程造成的瞬时访问/共享锁时，会在约五秒的上限内重试，永久错误或目标竞争仍立即失败。
- Windows 原生回归覆盖确定性重试、重试上限、目标不覆盖，以及从固定依赖构建真实 Harness payload 后通过生产提交路径完成 Web 启动和托管入口验证；NSIS 与整包安装、启动、删除烟测继续通过。

## Beta 7 热修复

- Windows 删除正在运行或被占用的 Osverse 托管 CLI 时，现在返回专用 `REMOVAL_IN_USE` 状态，并明确提示关闭相关终端和应用窗口后重试。删除事务仍会完整回滚 shim 与工具目录，不会留下半份恢复记录，也不会粗暴结束其它 Node 进程。
- 修复 OpenCode Desktop 与 Cockpit Tools 这类会删除自身的 Windows 卸载器被 Osverse 文件锁阻断或在成功后误报失败的问题。Osverse 会把经过重新验证的卸载器身份锁保留到进程创建成功，随后立即释放；因此启动前仍无法替换目标，启动后卸载器可以正常清理自身。
- Windows 原生回归会真实持有 Harness 运行时文件并验证专用占用状态与完整回滚，还会验证卸载器锁在进程仍运行时已经释放、自删除事务返回成功，以及所有启动失败路径都关闭已转移的句柄。

## 重点变化

- 检测用户真实命令路径中的 Kimi Code，并展示全部安装位置、解析目标和版本。
- 固定 Kimi Code `0.36.1` 六个平台制品的官方 URL、精确长度与 SHA-256；当前 Linux x64 和 Windows x64 应用启用事务式安装。
- ZIP 只允许一个固定普通可执行文件，提交前必须精确通过 `kimi --version`；版本目录不可变，命令入口与 PATH 原子切换并可回滚。
- 受管包装器关闭 Kimi 上游自动升级，防止后台下载绕过 Osverse 的统一验证。
- API 兼容矩阵支持 OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages，并使用 Kimi 原生 Provider 配置。
- 保留服务商提供的原始模型 ID；`osverse` 仅为本地 Provider/模型别名，不会出现在发往 API 的 `model` 字段中。
- 备份并原子更新 `~/.kimi-code/config.toml`，保留无关 TOML，拒绝覆盖没有 Osverse 所有权标记的同名配置。
- 总览、安装对话框、API 档案页、品牌图标、中英文 README、安全说明与使用指南同步更新。

## 验证

- 使用官方 Kimi Code `0.36.1` Linux x64 二进制完成真实流式端到端请求，验证 Bearer 凭据、规范化 Base URL 与精确模型 ID。
- 使用官方 Linux x64 与 Windows x64 Release 归档完成下载外的真实解压、版本和运行校验。
- 完整 Go、race、vet、前端测试、类型检查、生产构建、依赖审计以及 GitHub 原生 Windows/Ubuntu CI 作为发版门禁。

## English summary

Osverse 0.9 adds Kimi Code discovery, checksum-pinned standalone installation, launch, safe removal, and native third-party API profile support. It preserves existing external commands, installs without Node/npm, disables upstream self-update only for the managed runtime, and keeps the vendor's exact model ID on the wire.

The adapter backs up and atomically updates `~/.kimi-code/config.toml`, uses Kimi's native OpenAI Chat, OpenAI Responses, or Anthropic provider type, preserves unrelated TOML, and refuses unowned naming conflicts. Validation includes a real streaming request through the official Kimi Code `0.36.1` Linux binary plus official Linux and Windows archive verification.

Beta 2 also preserves `DSH_HOME` through the sanitized Windows and Linux launch environments, so DeepSeek Harness loads the same profile home that Osverse configures. Native Windows CI now builds the locked Harness payload, initializes a fresh `web` profile, and requires the HTTP interface to become reachable.

Beta 3 fixes the remaining Windows Harness managed-entry issues: terminal launch now invokes `.cmd` and `.bat` entries with `call`, and safe removal accepts the Osverse-managed `dsh.cmd` wrapper target while keeping the target confined to the current user's managed tool directory. The Windows gate now exercises the complete managed shim chain before packaging.

Beta 4 extends the same safe Windows removal support to the other Osverse-managed command wrappers, including Qwen Code, Kimi Code, and GitHub Copilot CLI. Wrapper removal remains constrained by component ID, expected command filename, and current-user managed tool root containment.

Beta 5 recognizes the official OpenCode Beta product name, executable, per-user installation directory, registry-based custom locations, and uninstaller on Windows. It also stops case-insensitive `claude.exe`, `codex.exe`, and `opencode.exe` CLI entries on PATH from being treated as proof that the corresponding desktop applications are installed. Native Windows regressions cover Beta discovery, CLI/desktop identity isolation, safe removal, Harness first launch, NSIS packaging, and install/launch/remove smoke.

Beta 6 hardens exact Windows MSIX identity matching and deterministic version selection, expands only `REG_EXPAND_SZ` uninstall paths through the Windows API, and makes DeepSeek Harness payload commits resilient to short-lived antivirus, indexing, or process-shutdown locks. The commit remains atomic and non-replacing, retries are bounded to about five seconds, and permanent errors or destination races fail closed. Native Windows CI exercises the production Harness commit, managed shim, Web startup, NSIS packaging, and package install/launch/remove path.

Beta 7 makes Windows removal outcomes accurate and actionable. A running managed CLI now returns `REMOVAL_IN_USE`, tells the user to close the related terminal or application window, and retains the existing complete rollback guarantee without terminating unrelated Node processes. For fixed-path OpenCode Desktop and Cockpit Tools uninstallers, Osverse keeps the revalidated identity lock through process creation and releases it immediately afterward, allowing legitimate self-removal without opening a pre-start replacement window. Native Windows regressions cover the locked Harness transaction, rollback integrity, transferred-handle lifetime, early-start failure cleanup, and a self-deleting desktop uninstaller.
