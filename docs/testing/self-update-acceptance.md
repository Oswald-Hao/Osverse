# Osverse 应用内更新验收

本清单用于从一个已发布旧版本升级到较新的 Osverse Release。测试账号和机器中不得放置真实 API Key。

## 所有平台

- [ ] 旧版本启动后只在发现更高语义化版本时提示；稳定版不会收到预发布版，预发布版可以升级到更新的预发布版或稳定版。
- [ ] 对话框显示当前版本、目标版本、Release 更新说明、下载大小和安装方式，关闭后不阻塞环境扫描。
- [ ] 直连与已验证的本机 HTTP、HTTPS CONNECT、SOCKS5 代理分别完成一次检查和下载。
- [ ] 断网、超时、错误长度、错误 SHA-256、错误仓库/标签/文件名均安全失败，不启动安装器，也不改变当前程序。
- [ ] 同一更新计划不能执行两次；等待 15 分钟后旧计划失效，重新检查可获得新计划。
- [ ] 更新后“设置 → Osverse 更新”显示新版本，环境扫描、API 档案和历史数据仍可读取。

## Windows 10/11 x64

- [ ] 从已安装版升级：校验完成后出现可见的 NSIS 安装程序，旧 Osverse 自动退出，确认安装后新版本可从原快捷方式启动。
- [ ] 从 portable `.zip` 中的单文件运行并更新时，仍使用经过校验的 NSIS，不要求先卸载旧版本。
- [ ] 取消 NSIS 不破坏旧版本；重新启动旧版本仍可再次检查更新。

## Ubuntu AppImage

- [ ] 更新包写入完成并校验后才替换当前 AppImage；文件名和启动入口保持不变，新版本自动重启。
- [ ] 目标目录不可写或重启失败时恢复旧文件；`.osverse-previous` 保留一个可恢复版本。

## Ubuntu `.deb`

- [ ] 校验后由系统软件安装器打开本地 `.deb`，用户仍需确认系统安装；不会打开浏览器或 GitHub 下载页。
- [ ] 取消系统安装后当前版本继续工作，之后可以重新检查。

## Ubuntu 便携 `.tar.gz`

- [ ] 只提取发布包根目录中的普通 `osverse` 文件；路径穿越、符号链接、重复二进制和超限归档均拒绝。
- [ ] 校验后原子替换当前二进制并重启；启动失败时恢复旧版本。

## macOS（安装包发布后启用）

- [ ] 同一检查、说明、确认和 SHA-256 流程选择匹配架构的官方 DMG。
- [ ] 校验后只调用 `/usr/bin/open` 打开本地 DMG，由用户确认替换应用；不执行前端传入的命令。
